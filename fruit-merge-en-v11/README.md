# Fruit Merge Game

## Shared leaderboard

Finished runs are stored in SQLite and shown in the same sidebar (Name field and Top 15 table). The page loads `GET /api/leaderboard` and submits a finished score with `POST /api/leaderboard`. Paths are same-origin so Caddy on fruitmergegame.net can proxy them.

The API is `server/leaderboard.py` (Python standard library only). It keeps one best score per display name, trims the name (blank becomes `You`, length capped at 20), and accepts only a non-negative integer score up to **10,000,000**. That cap is about three hours of the impossible case where every drop is a watermelon merge (821 points, 0.48s cooldown). Real runs are far lower. Posts are limited to 8 per minute per client address, and reads to 90 per minute. The process reads the client from the last `X-Forwarded-For` hop, which Caddy appends.

There are no accounts, passwords, or payment settings.

```bash
# API only, for the reverse proxy
python3 /opt/fruitmergegame/server/leaderboard.py \
  --host 127.0.0.1 --port 43124 \
  --db /var/lib/fruitmergegame/scores.sqlite

# Same-origin local preview (static game + API)
python3 server/leaderboard.py --host 127.0.0.1 --port 43124 \
  --db /tmp/fruitmerge-scores.sqlite --static site
```

Suggested layout on the machine that serves the site:

| What | Path |
| --- | --- |
| App code, including `server/leaderboard.py` | `/opt/fruitmergegame` |
| Static game (the `site/` directory) | `/var/www/fruitmergegame.net` |
| SQLite database | `/var/lib/fruitmergegame/scores.sqlite` |
| Listen address | `127.0.0.1:43124` only |

Caddy can keep serving the static files and forward the API:

```caddy
fruitmergegame.net {
    handle /api/* {
        reverse_proxy 127.0.0.1:43124
    }
    handle {
        root * /var/www/fruitmergegame.net
        file_server
    }
}
```

Example service:

```ini
[Service]
WorkingDirectory=/opt/fruitmergegame
ExecStart=/usr/bin/python3 /opt/fruitmergegame/server/leaderboard.py --host 127.0.0.1 --port 43124 --db /var/lib/fruitmergegame/scores.sqlite
Restart=on-failure
```

Copy this project to `/opt/fruitmergegame` and copy `site/` to `/var/www/fruitmergegame.net`. Create `/var/lib/fruitmergegame` writable by the service user. Do not publish port 43124.

## Difficulty

Drops are a little easier to match. Each size still uses the original odds, and the auto-drop timer and danger line are unchanged. Two things changed in `pick()`:

- Each size has two common fruits. About 60% of drops of that size are one of those two. The other fruits of that size still drop the rest of the time, and every fruit can still be merged.
- If that size is already in your hand, was one of the last three drops, or is on the board, about 45% of drops of that size repeat one of those fruits.
